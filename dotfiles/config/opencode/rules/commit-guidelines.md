## Commit Guidelines

When asked to commit changes, follow these guidelines:

1. **Check staged files** first using `git status` to understand what will be committed
2. **Use conventional commits** format: `type(scope): description`
3. **Include relevant emojis** to make commits fun and engaging
4. **Write descriptive messages** that explain the changes made
5. **Group related changes** in a single commit when appropriate
6. **Never stage new files** - only commit what's already staged

### Example commit structure:
```
feat(musicbox-web): enhance audio visualization with log frequency bands and gradient styling 🎵


```

### Types to use:
- `feat`: New features
- `fix`: Bug fixes
- `refactor`: Code restructuring
- `docs`: Documentation changes
- `test`: Adding or modifying tests
- `chore`: Routine tasks, tooling changes, etc.

### Emoji Guide:
- ✨ For new features
- 🐛 For bug fixes
- 🔧 For configuration changes
- 📈 For performance improvements
- 🎨 For UI/UX improvements
- 🚀 For optimizations
- 🔥 For removals
- ✅ For updates
- 📝 For documentation
